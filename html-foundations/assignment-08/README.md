# Assignment 2.8: Accessible Mentorship Application Form

An application form for a mentorship programme, built with plain HTML only. Every control has its own label, related choices are grouped with `<fieldset>` and `<legend>`, and the native constraint attributes do the checking.

## Project details

- **Method:** `POST`. The form includes personal details such as an email address, and `POST` sends them in the request body, not in the URL.
- **Action:** `/submit-application`. This is a placeholder endpoint. No backend exists, so the form does not store or send anything. A real site would also need HTTPS, because `POST` does not encrypt data by itself.
- **Labels:** every control has a `<label>` connected with `for` and a unique `id`. The placeholders are only examples and are never used as labels.
- **Groups:** Personal Information, Development Information and Availability are `<fieldset>` groups. Gender, Areas of Interest and Preferred Learning Track are nested groups, each with its own `<legend>`.
- **Privacy:** only the fields in the brief are collected. There is no address, ID number or other extra data. Phone, gender, areas of interest and GitHub are optional.
- **Validation:** checked with the W3C Markup Validator.

## Control table

| #   | Control                                                                                      | Input type                                         | Constraints                                                               | Why I chose it                                                                                                                                                                                                                                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Full name (`fullName`)                                                                       | `<input type="text">`                              | `required`, `minlength="2"`, `maxlength="100"`, `autocomplete="name"`     | Names have no fixed format, so plain text is the only type that fits. `minlength` and `maxlength` stop empty or very long entries. It is required because the programme needs to know who is applying.                                                                                                                                                         |
| 2   | Email (`email`)                                                                              | `<input type="email">`                             | `required`, `autocomplete="email"`                                        | The browser checks that the value looks like an email address and phones show a keyboard with the @ key. It is required because it is how the programme replies.                                                                                                                                                                                               |
| 3   | Phone (`phone`)                                                                              | `<input type="tel">`                               | `autocomplete="tel"`                                                      | `tel` gives phones a number keypad. I did not add a pattern because phone formats are different in each country. It is optional because email is enough to contact someone, so a phone number is not necessary data.                                                                                                                                           |
| 4   | Date of birth (`dob`)                                                                        | `<input type="date">`                              | `required`, `min="1940-01-01"`, `max="2026-11-05"`, `autocomplete="bday"` | The date picker gives one clear format and no typing mistakes. It is required because an age check needs it. `min` and `max` only block dates that are impossible, so I did not make up an age limit, because the programme's own review decides who is eligible. The `max` is a fixed date because this is HTML only. A real site would set it automatically. |
| 5   | Gender (`genderFemale`, `genderMale`, `genderNonBinary`, `genderPreferNot`)                  | `<input type="radio">` ×4, `name="gender"`         | none (optional)                                                           | Only one answer is possible and there are few choices, so radios show them all at once. It is optional and has a "Prefer not to say" choice because gender is not needed for an application and nobody should be forced to answer. The group sits in a `<fieldset>` with a `<legend>`.                                                                         |
| 6   | Current experience level (`experienceLevel`)                                                 | `<select>` with `<option>`                         | `required`                                                                | One choice from four levels, ordered from beginner to advanced. A `<select>` keeps the form short. The first option has an empty value and is disabled, so `required` catches anyone who has not chosen.                                                                                                                                                       |
| 7   | Areas of interest (`interestHtmlCss`, `interestJs`, `interestAccessibility`, `interestCs50`) | `<input type="checkbox">` ×4, `name="interests"`   | none (optional)                                                           | More than one interest can be chosen, so checkboxes are right and radios would not be. They share one `name` and have different `value`s and `id`s. It is optional because some applicants do not know yet. Grouped in a `<fieldset>`.                                                                                                                         |
| 8   | Preferred learning track (`trackFrontend`, `trackFullstack`, `trackFoundations`)             | `<input type="radio">` ×3, `name="learning_track"` | `required`                                                                | Only one track can be chosen, and three options are few enough to show together. `required` on one radio makes the whole group required, so the programme can place the applicant. Grouped in a `<fieldset>`.                                                                                                                                                  |
| 9   | GitHub profile URL (`githubUrl`)                                                             | `<input type="url">`                               | `pattern="https://github\.com/.+"`, `title`                               | `url` checks that the value looks like a web address. The pattern limits it to a GitHub profile with a username after the slash, and the `title` explains that rule. It is optional because a beginner may not have a profile yet.                                                                                                                             |
| 10  | Why do you want to join (`motivation`)                                                       | `<textarea>`                                       | `required`, `minlength="50"`, `maxlength="500"`, `rows="5"`               | The answer is a few sentences, so it needs a multi-line box. `minlength` stops one-word answers and `maxlength` keeps it short. It is required because it is the main way to see the applicant's goals.                                                                                                                                                        |
| 11  | Weekly time commitment (`availability`)                                                      | `<select>` with `<option>`                         | `required`                                                                | Three hour ranges give answers that are easy to compare, and a `<select>` keeps the form short. The empty disabled first option works with `required`, as in the experience field.                                                                                                                                                                             |
| 12  | Agreement to the rules (`rulesAgreement`)                                                    | `<input type="checkbox">`                          | `required`, `value="agreed"`                                              | It is a single yes answer, so one checkbox fits. `required` means the form cannot be sent without agreeing. `value="agreed"` means the submitted data says what was agreed, and without it the browser would send "on".                                                                                                                                        |
| 13  | Submit Application                                                                           | `<button type="submit">`                           | none                                                                      | A real button, so it works with the keyboard and screen readers announce it as a button. It sends the form to the action.                                                                                                                                                                                                                                      |

## Notice

This form does not send data anywhere. The email address and other examples in the placeholders are fictional.
